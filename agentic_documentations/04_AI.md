# AI Architecture

## Principle

Use AI selectively.

Deterministic code should handle:
- timers
- navigation
- question scoring
- progress calculations
- band arithmetic
- session state
- validation

AI should handle:
- explanations
- adaptive tutoring
- writing feedback
- speaking feedback
- practice generation
- error classification
- personalized recommendations

## Provider abstraction

Create one interface:

AIProvider
- chat()
- explain()
- classify()
- generatePractice()
- evaluateWriting()
- evaluateSpeaking()
- createStudyPlan()

Implement providers behind this interface.

## Provider routing

Default:
1. Free/low-cost provider
2. Secondary provider when primary rate-limits
3. Graceful local/static fallback

Candidate providers:
- Groq
- Cloudflare Workers AI
- other OpenAI-compatible providers

Do not hard-code one vendor into UI code.

## Free-first strategy

Use free quotas for development and early users where terms permit.

Cloudflare Workers AI currently provides a free daily allocation, while Workers Free provides serverless request capacity. Verify current model-specific restrictions before deployment.

Groq currently exposes free-plan model rate limits; build retry/backoff and provider fallback rather than assuming unlimited access.

## AI caching

Cache deterministic/repeatable outputs:
- explanations
- generated practice items
- resource summaries
- grammar explanations

Do not cache private learner submissions globally.

## Prompt architecture

Every AI task gets:
- system role
- task definition
- IELTS rubric/context
- learner context
- input
- output schema
- validation rules

Prefer structured JSON outputs.

## Writing evaluation

Return:

{
  "estimated_band": 6.5,
  "criteria": {
    "task_response": 6,
    "coherence": 6,
    "lexical_resource": 7,
    "grammar": 6
  },
  "strengths": [],
  "issues": [],
  "priority_actions": [],
  "rewrite_exercises": []
}

Never present this as official scoring.

## Speaking evaluation

Return:
- estimated criteria bands
- fluency observations
- vocabulary observations
- grammar observations
- pronunciation observations
- transcript annotations
- targeted drills

## Hallucination control

AI must not invent passage evidence.

For reading:
- answers must cite exact passage spans internally
- validate answer uniqueness

For writing:
- feedback must quote only short relevant learner text
- distinguish grammar facts from subjective style advice

## Rate limiting

Worker:
- per-IP rate limit
- per-session rate limit
- request size limit
- token budget
- exponential backoff
- provider failover

## AI fallback

If AI is unavailable:
- continue deterministic practice
- show static explanations
- allow offline lessons
- queue optional feedback for later
